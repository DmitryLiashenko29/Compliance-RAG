# Агент Критик — часть к КП2

Compliance RAG · Янаков Роман · Подготовлено 10 ноября 2026 года

## Что подготовлено к защите

Подготовлен набор из 30 вопросов с эталонными ответами, критериями проверки и ссылками на конкретные редакции документов. Дополнительно подготовлены 12 сценариев отдельной проверки Критика с фиксированными результатами поиска. Описаны его роль, предлагаемые входы и выходы, порядок реализации и оценка.

Это подготовка проверки и проектирование компонента. Реализация Критика и экспериментальные результаты в пакет не входят. Выбор Reddit и YouTube предложен для КП2; участник, готовящий документы, должен подтвердить включение этих редакций в общий корпус. Разметка требует второго просмотра командой.

Выбраны Reddit 2025–2026 годов и YouTube 2023 года. Диапазон шире 2022–2024 из первоначальной презентации; расширение нужно согласовать. При жёстком ограничении исходным периодом карточки Reddit требуют замены и новой проверки.

## Роль в системе

Критик получает исходный вопрос, план и найденные фрагменты. Он проверяет, подтверждают ли материалы необходимые части ответа и относятся ли они к нужной редакции и области действия.

При достаточных доказательствах Критик передаёт их Агенту Ответа. При нехватке сведений формулирует дополнительный поисковый запрос. При неоднозначности вопроса предлагает уточнение. Если поиск завершён, а подтверждений всё ещё нет, фиксирует недостаточность данных.

Планировщик должен сохранять ID шагов, Поиск — связывать найденные фрагменты с этими ID. Критик сможет указать, для какого шага не хватает доказательств.

## Предлагаемый вход

| Данные | Назначение |
|---|---|
| Исходный вопрос и необходимый контекст диалога | Проверка полного смысла запроса |
| Шаги плана с id, text, type, depends_on | Проверка покрытия частей вопроса |
| Найденный текст и стабильный ID фрагмента | Указание конкретных доказательств |
| Сервис, документ, полный SHA редакции, раздел | Проверка применимости и источника |
| Время записи архива и отдельная дата действия, если подтверждена | Проверка временных условий |
| Режим поиска и число уже выполненных попыток | Выбор следующего действия |

Формат требует согласования с авторами соседних агентов. Поля оценки сходства могут помогать сортировке, но не подтверждают наличие ответа.

## Предлагаемый выход

| Поле | Содержание |
|---|---|
| Решение | pass, search_more, insufficient или clarify |
| Объяснение | Краткая проверяемая причина |
| Подтверждённые части вопроса | Факты и ID подтверждающих фрагментов |
| Недостающие сведения | Какого условия, факта или редакции не хватает |
| Отношение версий | Совпадение, уточнение, изменение области действия или недостаточно данных |
| Следующий запрос | Конкретный запрос для поиска или уточнения |

Это проект интерфейса. Значения меток в эталоне следуют этому предложению.

## Проверка достаточности

Критик сопоставляет части вопроса с доказательствами. Если вопрос содержит два условия, подтверждение одного оставляет второе открытым. Например, фрагмент о запрете показывать удалённый контент не сообщает числовой срок удаления копии.

Для повторного поиска нужно передавать конкретный пробел. Общий запрос «найди ещё» затрудняет проверку того, улучшился ли результат. Предлагается ограничить число повторов, сохранять уже найденные фрагменты и прекращать повторение одинаковых запросов без новых данных.

Пустая или нерелевантная выдача позволяет судить о недостаточности предоставленных материалов. Метку отсутствия ответа во всём контрольном корпусе устанавливают при подготовке эталона.

## Проверка версий

Критик сравнивает один и тот же вопрос о правиле, учитывая сервис, документ, дату, адресата и условия применения.

В наборе есть три показательных случая.

- В Y1 перечислены президентские выборы США, а в Y2 этот элемент удалён. Это изменение области применения конкретного пункта.
- В R1 и R2 текст Rule 5 об использовании настоящего имени совпадает. Версионного конфликта в этом пункте нет.
- В R2 разъяснение приватности подробнее ограничивает исключения для публичных лиц. Это уточнение, которое нельзя автоматически считать противоположным правилом.

Если сравниваются разные даты, различающиеся требования могут быть ожидаемым изменением политики. Неразрешимый конфликт требует отдельной проверки совпадения условий и отсутствия способа определить применимую редакцию.

В контрольном наборе пока нет отдельно подтверждённых неразрешимых противоречий для одной даты и одной области применения. До измерения заявленной в презентации полноты обнаружения конфликтов нужно согласовать определение этой метрики и расширить соответствующую разметку.

## Как измерять результат

Для Критика фиксировать правильность решения на фиксированной выдаче, долю пропущенных недостаточных ответов и долю ошибочно заблокированных достаточных ответов.

Для полного пайплайна фиксировать полноту ответа, подтверждённость утверждений, корректность пункта и версии, поведение на вопросах без ответа и время работы.

Для обнаружения согласованного класса конфликтов оценивать и полноту, и точность. Полнота — найденные реальные конфликты, делённые на все размеченные реальные конфликты. Точность — реальные конфликты среди всех срабатываний. При отсутствии положительных примеров полноту нельзя содержательно оценить.

Сравнение обычного RAG, агентной системы и системы без Критика планируется на одинаковом наборе. Нельзя переносить целевые значения из презентации в графу полученных результатов.

## Текст выступления примерно на две минуты

Моя зона ответственности — Агент Критик и вопросы для проверки его работы.

К КП2 подготовлен набор из тридцати вопросов по зафиксированным редакциям правил Reddit и YouTube из Open Terms Archive. У каждого вопроса есть ожидаемый ответ либо основание для уточнения или признания нехватки данных. Для содержательных ответов указаны конкретная редакция и место в источнике. Выбор этих документов ещё нужно согласовать с общим корпусом команды.

Набор покрывает прямой поиск факта, ответы из нескольких условий, изменения между версиями и случаи, когда правило осталось прежним. Ещё есть пять вопросов, на которые в выбранных текстах нет ответа, и три неоднозначных вопроса.

Например, в двух снимках правил YouTube меняется перечень выборов, к которым применяется определённый пункт. Оба снимка записаны в один день. Поэтому одной календарной даты для идентификации версии недостаточно — мы фиксируем полный коммит архива.

Для проверки самого Критика дополнительно подготовлены двенадцать сценариев с заранее заданной выдачей Поиска. Один вопрос можно проверить с обеими нужными редакциями, с одной редакцией или с фрагментами другой темы. Это позволит отдельно оценить решение Критика при одинаковых входных данных.

Критик будет проверять, хватает ли доказательств для всех частей вопроса. Он сможет передать материалы Агенту Ответа, запросить дополнительный поиск, предложить уточнение или зафиксировать недостаточность данных после завершения поиска.

На следующем этапе я согласую формат обмена с другими агентами, реализую эти проверки и подключу повторный поиск. Затем сравним работу системы с Критиком и без него. Сейчас подготовлены проверочные материалы и описание компонента; результатов такого эксперимента пока нет.

## Короткие ответы на вопросы преподавателя

**Почему оценка сходства не решает задачу Критика?**

Фрагмент может быть похож по теме, но не содержать запрошенного срока, исключения или нужной редакции. Критик проверяет подтверждение конкретных частей вопроса.

**Как вы знаете правильный ответ?**

Он составлен по указанным диапазонам текста в конкретных коммитах. Для принятия набора командой предусмотрена повторная проверка другим участником.

**Почему есть вопросы без ответа?**

Они проверяют, не добавляет ли система правдоподобные сведения, которых нет в выбранном корпусе. Границы корпуса явно зафиксированы.

**Любое отличие версий является конфликтом?**

Изменение может быть уточнением или новым правилом для другой даты. Нужно сравнивать смысл и условия применения. В наборе эти случаи различаются.

**Есть ли уже работающий Критик?**

В рамках этого пакета подготовлены эталон, сценарии и описание поведения. Реализация и прогоны относятся к следующему этапу.

**Можно ли считать 30 вопросов независимыми?**

Часть вопросов связана одной темой. Для оценки нужно группировать связанные примеры и добавлять новые, не показанные разработчику, случаи для финальной проверки.
